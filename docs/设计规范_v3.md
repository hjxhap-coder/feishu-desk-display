## 1. §5 五问的答案

### Q1 三屏各自的版面与视觉层次

**共同骨架**（三屏一致，构成"一套东西"的感觉）：

```
┌──────────────────────────────┐ ← 外边框 1px
│  栏目名               11:38  │ ← 页眉：23px 标题 + 16px 时间
│  ══════════════════════════  │ ← 3px 粗线
│                              │
│         内容区                │
│                              │
│  ──────────────────────────  │ ← 1px 细线
│  栏目             11:38 更新  │ ← 页脚：11px
└──────────────────────────────┘
```

**待机屏 —— 主角是时间，书法是配角**

```
│  ┌──────┐        │      12:16      │
│  │ 快   │        │                  │
│  │ 雪   │        │  ──────────────  │
│  └──────┘        │  下一个日程      │
│  10月22日 星期四 │  15:00 项目周会│
│                  │  还有 2 小时 43 分 │
│                  │  ████████████████ │
│                  │  █ 今日 3 场会    █ │
│                  │  █ 待办 1/8 已完成█ │
│                  │  █ ▓▓░░░░░░░░░░░ █ │
│  □ 待机  □ 待办  □ 日程        │ ← 底部反白按键带
```

层次：大时钟(64px) > 下一个日程(15px) > 今日概览(反白卡) > 按键带(反白条) > 标签(11px)。
**书法是"气质"不是"信息"** —— 左侧占 35% 宽度但零信息量，让右侧的实用信息有呼吸空间。

**待办屏 —— 主角是"今天要做的"**

```
│ 待办                    12:16 │
│ ══════════════════════════════│
│ ▓▓▓▓▓▓░░░░░░░░░░░░░░░  1/8  │ ← 方块进度条
│ ☐ ■ 整理本周工作周报      今天│
│ ☐ ■ 代码评审：固件网络自愈 今天│
│ ☐   结算明细重算          明天│
│ ☐   质检通过率差距说明    01-24│
│ ☑   更新 wiki 闭环记录     │ ← 删除线
```

层次：进度条 > 未完成首行(粗) > 优先级实心方点 > 完成项(删除线) > 到期日(11px)。
**不做分组标签**：有外边框和 23px 标题之后，黑块分组太抢戏。改用**排序**补回信息 —— 逾期项自动排到最前。

**日程屏 —— 主角是时间轴**

```
│ 日程                    12:16 │
│ ══════════════════════════════│
│ ● 09:00  晨会                │ ← 竖轴：圆点连成一线
│ │       至 09:30 · 会议室 3A │
│ ○ 11:30  设计评审            │ ← 进行中：整块反白 + 空心大圈
│ │       进行中·剩余13分·至12:30│
│ ● 14:00  与同事 1:1        │
│ │       下一个·还有1小时43分  │
│ 08:00 ───●───●──┃───○───●─ 20:00│ ← 底部横轴
```

层次：进行中(反白) > 未完成首行(粗) > 时间(粗) > 副行(11px) > 刻度。

### Q2 日程屏下半屏：两方案对比

原问题：下半屏约 55% 是空的，补什么？

#### 方案 A：横向时间轴带（`TODO_RIBBON=axis`，**当前默认**）

事件按真实时刻落成小圆点，「现在」是一根贯穿的粗竖线，两端固定 08:00 / 20:00。

- ✅ **一屏看尽全天的疏密和位置关系** —— 三个会挤在上午还是散在全天，扫一眼就知道
- ✅ 固定 08:00–20:00，位置可预期，跨天对比有参照
- ✅ 和上方竖轴形成呼应（同一套"时间→位置"语汇）
- ❌ 圆点要眯眼找，解读成本高于文字
- ❌ 吃掉 28px 高度，且 20:00 之后/08:00 之前的事件落在轴外
- ❌ 会议很多时圆点挤成一串，密集区反而看不清

#### 方案 B：空档提示 + 下一场倒计时（`TODO_RIBBON=gap`）

一行「空闲 12:16–15:00（2 小时 43 分）」，一行「下一场 15:00 项目周会 · 还有 2 小时 43 分」。

- ✅ **直接给结论，零解读成本** —— 摆件要回答的是"我什么时候有空"，不是"给我一张图我自己算"
- ✅ 文字比圆点更适合 1-bit（11px 粗体字远比 3px 圆点清晰）
- ✅ 和待机屏的倒计时形成同一套语言
- ❌ 丢掉全天的疏密感
- ❌ 会议多时"最大空档"本身不可信（可能都是碎片化空隙）
- ❌ 一天的日程如果都在 8–20 点内，空档就退化成一条无用信息

#### 结论

**当前默认 A**，因为它承载的是"日历"这一屏的本质；**如果你更看重"我什么时候有空"这一个结论，切 B**。

一行命令切换：
```bash
TODO_RIBBON=gap python3 render_v3.py --mode schedule
```

两方案产物：`out/v3/sched_axis_2x.png` / `out/v3/sched_gap_2x.png`，对比图 `_ribbon_compare.png`。

> 注：事件 ≤3 条时上半屏会空一截（方案 A 尤其明显）。真实日程通常 4–6 条，
> 这个问题会自然消失；若要彻底解决，可以让列表行高随事件数自适应（已实现，见 §4）。

### Q3 反白块第三处用在哪？该不该再用？

**先定规则，再谈用在哪。**

反白块是 1-bit 屏上**强度最高的元素** —— 整块反色在黑白屏里等于"喊话"。
所以规则是：

> **每屏最多 1 处「语义反白」（强调某个内容区）。**
> 「功能反白」（固定构件，如按键带、错误提示卡）不算在内，但不得与语义反白同屏相邻。

v3 实际用量：

| 屏 | 语义反白 | 功能反白 |
|---|---|---|
| 待机 | 今日概览卡 | 底部按键带 |
| 待办 | **无** | 错误提示卡（仅未授权时） |
| 日程 | 进行中的事件 | 无 |

**待办屏刻意不给反白** —— 它是平铺列表，任何一条都不比别的更重要；给「今天」那组加反白条会暗示"其他的不用看"，是错的引导。如果以后一定要分组，优先用**反白小标签**（宽度贴合文字的黑底白字小块）而不是整条反白，强度低一个量级。

**第三处（若要加）建议放在：日程屏的"现在"**—— 但那已经由竖轴的空心大圈 + 粗竖线标记承担了，加反白块会重复。

**结论：反白块不该再加了。** 三屏各一处语义反白已经是上限，再多就变"网页高亮"。

### Q4 「进行中 / 下一个」除了反白和空心圈还能怎么区分？

现在这套：

| 状态 | 图形 | 文字 | 排版 |
|---|---|---|---|
| 进行中 | 整块反白 + 竖轴空心大圈(7px) | `进行中 · 剩余 13 分` | 反白块内白字 |
| 下一个 | 竖轴实心点(3px) | `下一个 · 还有 1 小时 43 分` | 标题粗体 |
| 普通 | 竖轴实心点(3px) | `至 12:30 · 会议室 3A` | 标题常规 |

**再加一条就够，别叠更多形状**：

1. **倒计时文字**（已实现）—— 「剩余 13 分」「还有 1 小时 43 分」。
   这是唯一**不用解读**的区分方式：反白要理解"反色=重要"，空心圈要理解"圈=将来"，
   而「还有 43 分」直接读。1-bit 屏上文字的辨识度也远高于 3px 圆点。
2. 不要再加：颜色（没有）、闪烁（1-bit 屏做不出灰度渐变、且耗电）、
   字号差（反白块里已经是白字，再变字号会挤）、图标（没有可用字形）。

**倒计时是这套语汇的主角**：待机屏的「还有 2 小时 43 分」、日程屏的「进行中·剩余 13 分」、
底部横轴的粗竖线，三处说的是同一件事。

### Q5 统一视觉语言规范（具体数值）

| 元素 | 规格 | 代码位置 |
|---|---|---|
| 外边框 | 1px 实线，离画布边 **5px** | `frame()` |
| 内容左右边距 | **12px** | `M` |
| 内容区上下边距 | **9px** | `M` |
| 页眉标题 | **23px** Songti SC Black，左对齐 | `header()` |
| 页眉时间 | **16px** STHeiti Medium，右对齐 | `header()` |
| 页眉粗线 | **3px**，y = 39 | `header()` |
| 页脚细分隔线 | **1px**，y = 275 | `footer()` |
| 页脚文字 | **11px**（自动提 W6），y = 279 | `footer()` |
| 栏目标签 | **11px**，字距 **2px** | `label()` |
| 正文 | Hiragino W6 **13–17px**（<14px 自动提 W6） | `font()` |
| 列表行高 | **24px**（待办）/ 按事件数 4–20px（日程） | |
| 圆点 | 实心 **r=3px**；空心圈 **r=7px**、线宽 2px | |
| 复选框 | **13px** 见方，线宽 1px，勾白线宽 2px | `checkbox()` |
| 进度条格 | 高 **8px**，格间距 2px，实心=已完成 | `seg_bar()` |
| 反白块 | 整块填黑，字填白；圆角=直角 | |
| 区块间距 | 标签→内容 **8px**；事件之间 **4–18px**；区与区 **16–20px** | |
| 竖轴 | x=20，点心 x=20，线宽 1px | |
| 底部横轴 | y=252，线宽 1px；「现在」竖线 **2px**、上下各 9/7px | `ribbon_axis()` |
| 留白原则 | 内容不满屏时**不补偿**，宁可留白 | |

**字距规则**：只有「栏目标签」类小字用 2px 字距制造印刷感；正文和数字**不加字距**
（数字加字距会破坏等宽对齐）。

**线宽只有三档**：1px（细线/分隔线）、2px（强调圆圈/竖标记）、3px（页眉主分隔线）。
不用 4px 以上 —— 在 400×300 上会变成"黑杠"。

## 3. 字体验证（推翻了一个想当然的结论）

约束原文：「任何 Light 字重、**任何衬线体**在小字号下都会碎」。

v3 页眉用了宋体（衬线体），所以必须实测而不是嘴硬。`check_font.py` 的结果
（文字「日程」，23px，4 倍画布 → 缩回 1x → 二值化）：

| 字体 | 灰度段数 | 1-bit 段数 | 孤立碎段(<3px) |
|---|---|---|---|
| **宋体黑 Songti SC Black** | 87 | **87** | **11** |
| 黑体 Hiragino Sans GB W6 | 77 | 77 | 20 |
| 中黑 STHeiti Medium | 78 | 78 | **53** |

**结论**：
1. **1-bit 化后段数一个没变** → 23px 下没有任何笔画被打散。
2. **碎得最厉害的是 STHeiti Medium**（53 个孤立碎段），不是宋体。
   真正的坑是**细字重**，不是衬线体 —— 宋体 Black 横画有厚度，天然抗阈值化。
3. 所以约束的准确表述是「**小字号 + 细字重**会碎」，大字用宋体黑成立。

> 判据说明：段数 = 逐行数连续黑段。笔画被打散 = 一根横被切成多段 = 段数暴涨。
> 孤立段数 = 打碎的残渣（长度 <3px 的黑段）。

## 4. 边界情况处理

### 日程事件数 → 字号档位

事件区可用高度固定（44–212px），每档都算过总高：

| 事件数 | 时间 | 标题 | 副行 | 间距 | 总高 |
|---|---|---|---|---|---|
| ≤3 | 16px | 17px | 14px | 18px | 156px |
| ≤4 | 14px | 15px | 13px | 8px | 156px |
| ≤5 | 13px | 14px | 12px | 6px | 170px |
| ≤6 | 12px | 13px | 11px | 5px | 186px |
| ≤7 | 12px | 12px | 10px | 4px | 182px |
| ≥8 | 12px | 13px | **无副行** | 4px | 152px |

放不下时底部提示「还有 N 项」（预留 18px）。

**反白事件额外占 8px 呼吸空间** —— 否则反白块会压掉上一条的副行和下一条的时间。
这是实测出来的：6 条日程时反白块切掉了「至 11:00」和「12:30」。

### 其他

- 零时长日程（飞书上就是瞬时提醒）：`end_ts` 置 0，不编结束时间，副行只显示地点
- 待办未授权：整块反白提示「待办未授权 / 缺权限 task:task:read」，
  **不能显示成空列表** —— 1-bit 上「没有待办」和「待办没权限」长得一模一样
- 书法素材缺失时自动跳过，左栏留空不崩
