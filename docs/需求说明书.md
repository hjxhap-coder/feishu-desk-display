# 飞书待办日程摆件 — 需求说明书

> 这份文档可以直接交给其他 AI 做视觉设计或实现。
> 现有实现：Mac 端 Python + PIL 渲染三屏 → ESP32-S3 通过 HTTP 拉 15000 字节 1-bit 帧贴到 400×300 屏。

---

## 0. 一句话概括

一台放在桌面上的 ESP32-S3 摆件，屏幕实时显示**飞书待办**和**飞书日程**。
板子上有 3 个按键，分别切换「待机 / 待办 / 日程」三个界面。

---

## 1. 硬件（不可改）

| 项 | 值 |
|---|---|
| 主控 | ESP32-S3 v0.2，16MB Flash，8MB Octal PSRAM |
| 屏幕 | RLCD，**400 × 300，1-bit 单色（纯黑白）** |
| 屏接口 | SPI3_HOST，MOSI=12, SCLK=11, DC=5, CS=40, RST=41, TE=6 |
| 帧格式 | 15000 字节，行优先，MSB 在前，**1 = 白（纸面）**，0 = 黑（墨） |
| 按键 | 板载 3 个，GPIO 待定 |

**引脚占用（选按键 GPIO 时必须避开）**
- 屏幕：5 / 11 / 12 / 40 / 41
- PSRAM：33–37 ｜ Flash：26–32 ｜ USB：19 / 20 ｜ UART：43 / 44
- Strapping：0 / 3 / 45 / 46

---

## 2. 架构（已定，别推翻）

1. **排版全部在 Mac 上做完**，含中文字形。ESP32 只负责把 15000 字节的像素贴到屏上。
   —— 不在 MCU 上做 CJK 字体渲染，那是另一个量级的工程。
2. **飞书凭据只留在 Mac**。板子永远拿不到任何飞书密钥，它只认 HTTP 和串口。
3. **1-bit 屏只有黑白两色**。层次靠「反白块 / 粗细分隔线 / 字重 / 留白」堆，**不靠颜色**。
4. 飞书权限未审批时用 mock 数据顶替，**原型任何时候都能跑通、能演示**。

### 数据流

```
lark-cli ──> lark_pull.py ──> state.json ──> render.py ──> 1-bit 帧
                                        └─> serve_screen.py ──HTTP──> ESP32
```

### HTTP 协议（已实现）

```
GET /s/standby.bin     15000 字节 packed 1-bit 帧
GET /s/todo.bin
GET /s/schedule.bin
GET /s/<mode>.png      2x 预览
GET /health            "ok <bytes> <time>"
```

- 待机屏有钟，按 **15 秒 TTL** 重画；另两屏跟随 `state.json` 的 mtime。
- 按键切模式后**立即拉帧**，不等轮询周期。

## 3. 三屏内容

### 3.1 待机屏（standby）

- **大时钟**（主角，`HH:MM`，超大字号）
- 日期：`10月22日 星期四`（小字，字距拉开当副标题）
- 细分隔线
- 「下一个日程」：小标签 + `14:00 与同事 1:1`
- 「待办」：标签 + `3/8` + **分段进度条**（一格一个任务，实心 = 已完成）
- **底部整条反白带**，像真设备的按键说明：`□ 待机   □ 待办   □ 日程`

### 3.2 待办屏（todo）

- 页头：`待办` + 右侧当前时间，下面一条**粗线**
- 进度条 + `3/8` 计数
- 任务列表，每行：
  - 复选框（已完成 = 实心方块 + 一道白勾；未完成 = 空心方框）
  - 高优先级：文字前一个**实心方点**
  - 任务文字（未完成首行用粗体，完成的加**删除线**）
  - 右侧右对齐到期时间（`今天` / `明天` / `10-24`）
- 超出可见区时底部显示「还有 N 项」
- 页脚：`待办清单` ｜ `11:38 更新`

### 3.3 日程屏（schedule）

- 页头：`日程` + 右侧当前时间
- 左侧时间轴：竖线 + 圆点
  - 普通事件 = 实心小点
  - 下一个事件 = **空心大圈**
  - 进行中事件 = 整块**反白**，轴上是白点
- 每条事件：`09:00` ｜ 标题 ｜ `至 09:30 · 会议室 3A`
- 页脚：`今日 4 项` ｜ `11:38 更新`

> **待改进**：日程屏下半部分（约 55% 高度）目前是空的，需要补内容 —— 计划加一条「今日时间轴」
> （如 08:00–20:00 横带，事件按时间比例定位，当前时刻用竖标记）。

## 4. 字体约束（1-bit 屏的硬约束）

在 400×300 真实 1-bit 化后实测得出：

- **11px 是可读下限**，低于这个字号笔画会被阈值化打散成渣。
- Hiragino Sans GB **W3 12px 起才稳**。
- **任何 Light 字重、任何衬线体在小字号下都会碎**。
- 做法：字号 < 14px 且字重是常规/中粗时，**自动提到 W6**。
- 分隔线宽度提到 1px（细线在 1-bit 上会断）。

本机可用字体（**没有 PingFang.ttc**）：
`Hiragino Sans GB.ttc`（W3 index 0 / W6 index 2）、`STHeiti Medium.ttc`、`Songti`、`Arial Unicode.ttf`

## 5. 设计任务（交给其他 AI 的部分）

请针对下面几条给出**具体可执行的视觉方案**，不要泛泛而谈：

1. **三屏各自的版面与视觉层次**，在「只有黑白两色 + 400×300 + 11px 最小字号」的约束下怎么排最好看。
2. **日程屏下半屏怎么填**：是加「今日时间轴横带」，还是别的信息（空档提示、下一场倒计时、会议室位置…）？给两种方案对比。
3. **反白块怎么用**：待机屏底部按键带 + 日程屏进行中事件已经用了一处反白，第三处该用在哪？还是不该再用了？
4. **「进行中 / 下一个」这两个状态，除了反白和空心圈，还能怎么区分**？
5. 三屏之间要不要有**统一的视觉语言**（页头/页脚/字距/分隔线粗细），怎么定一套规范。

### 设计约束（必须遵守）

- 1-bit 黑白两色，**不能出现灰度或颜色**
- 字号 ≥ 11px
- 中文优先用 Hiragino Sans GB / STHeiti，小字必须加粗
- 目标是「看起来像一台精致的桌面设备」，不是「像一张网页截图」
- 大量留白优于塞满信息

## 7. 现有代码位置

```
desktop/                Mac 端：拉数据 + 渲染 + 服务
  lark_pull.py                   lark-cli 拉任务+日程 → state.json（原子写，支持 --watch）
  mock_state.py                  造同形状假数据，无权限时顶替
  render.py                      三屏渲染器
  serve_screen.py                多模式端点 + 后台自动拉取
  state.json                     当前数据（mock）
  out/*.png                      渲染产物预览

main/                    固件
  main/main.cpp                  todo 模式（TODO_MODE=1）
  main/todo_config.h             WiFi 凭据 / Mac 地址 / 轮询间隔
```

`state.json` 的形状：

```jsonc
{
  "updated_at": "2026-10-22 11:38",
  "tasks": [
    { "text": "整理本周工作周报", "done": false, "pri": "high", "due": "今天" }
  ],
  "events": [
    { "title": "与同事 1:1", "start_hm": "14:00", "end_hm": "14:30",
      "location": "线上", "now": false, "next": true }
  ],
  "next_event": { /* 同 events 的一项 */ },
  "open_tasks": 5,
  "total_tasks": 8
}
```

- `pri`：`"high"` / `"low"` / `""`
- `events[].now`：正在进行 ｜ `events[].next`：下一个
